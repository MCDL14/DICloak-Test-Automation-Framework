# 创建使用已有代理的环境并成功打开：设计说明

## 目标

在现有 P0【环境管理】用例组中增加一个自动化用例：创建名为 `测试已有代理` 的环境，将代理设置切换为【已有代理】，在占位符为 `请选择已有代理` 的可搜索下拉框中输入 `7897`，选择当前下拉匹配结果中的第 1 项，保存并打开环境。打开后最多等待 60 秒，确认本次启动产生的 `GinsBrowser` 主进程存在；随后关闭并删除测试环境。

## 前置条件与数据所有权

- 【代理管理】中已经存在能够被关键字 `7897` 搜索到的代理。
- 该代理可用于正常打开环境。
- 用例直接依赖该已有代理，不负责创建、修改、检测或删除代理。
- 用例只清理自身创建的 `测试已有代理` 环境。
- 如果没有匹配结果、无法选中已有代理或该代理无法启动环境，让当前用例按实际操作失败；不自动补建代理或更换搜索关键字。

## 实现边界

- 正式用例放在 `tests/p0/environment_management/test_43_create_environment_with_existing_proxy.py`。
- 复用现有 `unittest`、`CDPDriver`、`LoginPage`、`EnvironmentPage`、进程检测和环境清理结构。
- 已有代理下拉框的定位、搜索、首项选择和选中状态读取集中补充到 `pages/environment_page.py`。
- 快速契约测试放在 `tests/p1/test_environment_existing_proxy_drawer.py`。
- 在正式代码落地前，先在系统临时目录创建一次性验证脚本，连接当前通过 CDP 启动的 DICloak，验证真实页面结构和完整业务流程；临时脚本不进入 Git。
- 不验证代理地址、代理类型、代理连通性、代理地区、出口 IP 或浏览器页面内容。

## 页面对象设计

`EnvironmentPage` 增加已有代理场景专用能力：

1. 判断活动创建环境抽屉中，占位符为 `请选择已有代理` 的下拉输入框是否可见。
2. 点击该输入框并填入搜索关键字 `7897`。
3. 等待 Element Plus 当前可见下拉面板中至少出现一个可选择且未禁用的结果。
4. 点击当前可见结果列表中的第 1 项。
5. 等待可见下拉面板关闭，并从选择组件中读取非空的已选代理显示文本；不能仅把尚未提交的搜索词 `7897` 当作选中值。

页面对象只暴露业务所需的最小接口，不抽象整个项目的通用下拉组件，也不把 DOM 定位脚本放进 P0 用例。

## 正式用例流程与断言边界

正式用例严格对应以下预期结果：

1. 进入【环境管理】后，【创建环境】按钮可见且可点击。
2. 点击【创建环境】后，创建环境抽屉已展开。
3. 输入 `测试已有代理` 后，环境名称字段值与输入一致。
4. 选择【已有代理】后，占位符为 `请选择已有代理` 的下拉选择框可见。
5. 输入 `7897` 并选择第 1 项后，下拉面板关闭且组件存在非空的已选代理显示文本，代表已成功搜索并选中已有代理选项。
6. 点击【确定】后，创建抽屉关闭，环境列表显示 `测试已有代理`。
7. 记录打开前的 `GinsBrowser` 主进程集合，点击【打开】后最多等待 60 秒；检测到至少一个本次新增的主进程即通过。超时未检测到时，将当前用例记录为 Fail，测试运行器继续执行后续用例。

不增加上述预期结果以外的业务断言。环境关闭状态和环境消失仅作为关闭、删除及异常清理的操作同步条件。

## 关闭、删除与异常处理

检测到新启动的 `GinsBrowser` 主进程后：

1. 等待环境操作进入可关闭状态。
2. 点击【关闭】。
3. 如果出现关闭确认框，点击【确定】或【确认】。
4. 等待环境回到可打开状态。
5. 精确选择 `测试已有代理`，通过批量删除动作删除该环境。

用例开始前按精确名称清理可能残留的同名环境。`finally` 中保留尽力清理：重新进入环境列表，若同名环境仍处于打开状态则先关闭并确认，再删除同名环境；清理失败只记录日志，不替换用例主体的原始失败。已有代理本身始终保留。

## 临时验证门禁

正式仓库代码之前，在 `/tmp/dicloak_existing_proxy_environment_probe.py` 中验证：

1. 创建按钮状态与抽屉打开。
2. 名称填写。
3. 切换【已有代理】后出现 `请选择已有代理`。
4. 输入 `7897`，选择当前匹配列表的第 1 项，并读取非空选中值。
5. 保存后列表显示环境。
6. 60 秒内检测到新增 `GinsBrowser` 主进程。
7. 关闭、确认并删除环境。
8. 检查没有残留同名环境。

只有临时脚本完整跑通后，才开始 P1 契约测试和正式实现。

- 运行新增 P1 测试，并回归上一条自定义代理抽屉测试及已有创建环境抽屉相关测试。

- 使用当前 CDP DICloak 运行正式 P0 用例，确认完整生命周期。
- 运行 Python 语法编译和 `git diff --check`。
- 验证正式用例常量为环境名 `测试已有代理`、搜索关键字 `7897`、启动超时 `60` 秒。
